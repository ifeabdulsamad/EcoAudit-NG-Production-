1 High-Level Architecture

EcoAudit NG is a fully client-side React SPA — all heavy computations (energy calculations, solar matching, local report generation) happen in the browser. Supabase is only used for auth persistence and saving audit history. The app follows a Context + useReducer state management pattern with no external state library (no Redux, no Zustand).

React 19 SPA (Single Page Application) ├── Context Providers // wraps entire app ├── 3-Step Audit Wizard // /audit page ├── Calculation Engine // synchronous, no server needed ├── Dashboard // results display ├── Supabase // auth + database (external) ├── Paystack // Nigerian payments (external) └── Gemini API // optional AI reports (external)

2 Provider Hierarchy

The app is wrapped in 3 nested context providers in App.jsx. This is the entry point for all data flow:

export default function App() { return ( <BrowserRouter> <TestingModeProvider> // Controls testing/demo mode <AuthProvider> // Supabase auth (user, sign in/out) <AuditProvider> // Audit form state & results (useReducer) <Navbar /> <Routes> <Route path="/" element={<Landing />} /> <Route path="/audit" element={<Audit />} /> <Route path="/dashboard" element={<Dashboard />} /> <Route path="/my-audits" element={<MyAudits />} /> <Route path="/pricing" element={<Pricing />} /> </Routes> </AuditProvider> </AuthProvider> </TestingModeProvider> </BrowserRouter> ); }

💡 Key Insight

Data flows down via React Context. Components update state by calling dispatch actions (e.g. setResults(), setStep()) or callbacks from context. There is no prop drilling — any component can access audit state by calling useAudit().

4 Form Persistence

The app automatically saves form progress to localStorage so users can recover from accidental page refreshes or tab closures.

// Draft Recovery Flow User types in form → useFormPersistence hook (debounced 1 second) → saveFormDraft() → localStorage key: "ecoaudit_form_draft" User refreshes or returns later → DraftRecoveryDialog checks hasFormDraft() → If draft < 60 minutes old → shows dialog → restoreDraft() → loads from localStorage → dispatches to AuditContext User completes audit → clearFormDraft() removes the draft from localStorage

Key Features

  • Debounced saving (1 second) — avoids writing on every keystroke
  • beforeunload listener — saves immediately if the user closes the tab
  • 24-hour expiry — drafts older than 24 hours are automatically deleted
  • 60-minute recovery window — only shows the dialog if the draft is less than 60 minutes old

5 Calculation Engine

This is the heart of the application — a synchronous function that takes the audit data and returns comprehensive energy analysis results.

// handleSubmit() in Audit.jsx const results = calculateAudit(auditData); // synchronous, no API call const solarData = estimateSolar(results); // runs on calculation output setResults({ ...results, solarData }); // stored in context navigate("/dashboard"); // redirect

What `calculateAudit()` computes

1️⃣ Appliance Energy Consumption

For each appliance: dailyKwh = (wattage × quantity × hoursPerDay) / 1000. Then splits between grid (₦65/kWh) and generator (diesel formula) based on grid hours per day. Also calculates CO₂ per appliance.

2️⃣ Generator Fuel Consumption

dieselConsumption = kVA × 0.8 × loadFactor × 0.28 L/kWh. Uses actual user fuel spend if provided (from Step 3 form), otherwise calculates from formula. Diesel cost: ₦1,650/L.

3️⃣ Energy Score (0-100)

Starts at 68 (neutral), then adjusts based on 5 factors:

  • Appliance efficiency ratings — ±10 points
  • Grid vs generator ratio — more grid = higher score (±10)
  • Cooling load percentage — high cooling = lower score (-12 to +5)
  • Spend vs benchmark — compared to industry averages for business size (-15 to +10)
  • Generator hours — heavy gen use = lower score (-10 to +5)

4️⃣ Recommendations & Carbon Comparisons

Recommendations are derived from actual data: low-efficiency replacements, gen reduction, cooling optimization, LED switching, solar viability. Sorted by priority (high → medium → low).

Carbon comparisons are Nigerian-contextual: "equivalent to X Lagos-Abuja road trips", "X months of average Nigerian emissions".

Matching Algorithm

matchSolarPackages() scores each package against the business profile:

  • Size match (+30 pts) — Does the package support the business size (micro/small/medium)?
  • Energy coverage ratio (+40 pts) — How much of the daily generator load can the system cover?
  • Affordability (+20 pts) — Is the monthly payment (over 36 months) within 1.5x the current fuel budget?
  • Goldilocks zone (+10 pts) — Is the system neither too small nor too big?

Returns a verdict: "Viable" (score ≥ 70), "Marginal" (score ≥ 50), or "Not Yet".

🌍 Solar Vendor Service

The solarVendorService.js implements a caching layer — fetches vendor data from a remote API with 24-hour cache TTL in localStorage. Falls back to the bundled merchant data if the network request fails. This allows you to update pricing without redeploying.

8 Authentication Flow

Authentication is handled entirely by Supabase Auth with support for email/password and Google OAuth.

// AuthProvider initialization AuthProvider mounts ├── supabase.auth.getSession() // Check for existing session ├── onAuthStateChange() listener // Subscribe to auth events └── Sets user state → renders children when !loading // Sign In flows Email/Password → supabase.auth.signInWithPassword({ email, password }) Google OAuth → supabase.auth.signInWithOAuth({ provider: 'google' }) → Redirect to Google → callback to /auth/callback Sign Up → supabase.auth.signUp({ email, password }) → Confirmation email sent → user confirms → session created Sign Out → supabase.auth.signOut()

🔐 Session Management

Supabase automatically manages JWT sessions via httpOnly cookies (for auth) and localStorage (for the session token). The onAuthStateChange listener updates the React context whenever the session changes, so the UI is always in sync with the auth state.

11 AI Report Flow (Gemini + Fallback)

The AI Report has a dual-path architecture — it tries Gemini first, then falls back to a local template-based report.

// Dual-path AI Report Generation AIReport component mounts ↓ generateAuditReport(auditResults) ↓ ├── IF VITE_GEMINI_API_KEY is set │ ├── buildPrompt() // Builds structured prompt with user's audit data │ ├── POST to Gemini 2.5 Flash API │ └── Returns plain-English report text │ └── IF API key missing OR API call fails └── generateLocalReport() // Client-side template-based report ├── Executive Summary (score + category) ├── Key Findings (top energy consumers) ├── Priority Actions (recommendations grouped by impact) ├── Solar Assessment (verdict + best match) └── Next Steps

Prompt Structure

`You are an energy efficiency advisor for Nigerian SMEs. The user has completed an energy audit... Write an audit report in plain English. Be direct, practical, and Nigerian context-aware. No jargon. Speak like a trusted advisor. Under 400 words. Structure: 1. One opening summary sentence 2. Top 2-3 energy problems observed 3. Three specific actions with estimated naira savings 4. A closing motivational line`

🤖 Cost Efficiency

Gemini 2.5 Flash costs ~$0.00015 per 1,000 tokens. Each audit report uses ~2,000–3,000 tokens, so each AI report costs less than ₦1. Even 1,000 reports/month = only ~₦750 total.

13 Testing Mode

A hidden feature that allows demonstrating the app without setting up Supabase. Perfect for demos, testing, and development.

// Testing Mode Activation enableTestingMode() → localStorage.setItem('ecoaudit_testing_mode', 'true') → Forces component re-renders ↓ When testing mode is ACTIVE: ├── AuthProvider returns FAKE_USER immediately (no Supabase call) ├── useFeatureGate returns 'business' plan (all features unlocked) ├── Navbar shows amber "TESTING MODE" banner at top └── Sign out disables testing mode FAKE_USER profile: ├── id: 'testing-user-123' ├── email: 'testing@ecoaudit.ng' └── plan: 'business' (all features accessible)

🧪 Why Testing Mode Matters

Since EcoAudit NG requires Supabase for auth and saving audits, testing mode is essential for: (1) demoing the app to potential users/investors without setup, (2) developing UI features without auth overhead, (3) testing the full freemium experience with business-tier access.

14 Database Schema

Supabase database with Row-Level Security (RLS) ensuring users only access their own data.

-- User profiles table CREATE TABLE profiles ( id UUID PRIMARY KEY REFERENCES auth.users ON DELETE CASCADE, email TEXT, full_name TEXT, plan TEXT DEFAULT 'free', -- 'free', 'pro', or 'business' audit_count INTEGER DEFAULT 0, created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW() ); -- Audits table CREATE TABLE audits ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), user_id UUID REFERENCES profiles(id) ON DELETE CASCADE, business_name TEXT, location TEXT, energy_score INTEGER, audit_data JSONB, -- Full form data results JSONB, -- Full calculation results created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW() );

Row-Level Security Policies

  • profiles: Users can SELECT and UPDATE only their own profile
  • audits: Users can SELECT, INSERT, and DELETE only their own audits
  • All policies use auth.uid() to identify the current user

15 Key Architectural Decisions

🏗️ What to Highlight in Your Interview

  1. Fully client-side computation — The calculation engine runs synchronously in the browser. No server round-trip needed. Results are instant. This makes the app fast and cheap to host (free on Vercel).
  2. Context + useReducer over Redux — For an app with a single form flow and results display, useReducer provides all the power of a state machine without the boilerplate of Redux. The AuditContext has 7 clear action types that map directly to user interactions.
  3. Progressive enhancement with gating — The basic audit is completely free. AI reports, PDF export, and audit history are gated behind subscriptions. This converts users before asking for payment.
  4. Graceful degradation everywhere — AI report falls back to local generation if Gemini is unreachable. Solar vendor data falls back to bundled data if the remote API fails. Form data persists to localStorage if the user refreshes.
  5. Testing mode for demos — A localStorage flag bypasses Supabase auth entirely, returning a fake user with business plan access. Essential for demonstrating the full product without setting up infrastructure.
  6. Nigerian-first design — The entire app is built for Nigerian realities: diesel generator calculations, Paystack (not Stripe), Naira formatting, local solar vendors, and carbon comparisons in Nigerian context (Lagos-Abuja road trips).
  7. Real vendor data, not estimates — The solar matching uses actual pricing from 4 verified Nigerian merchants with 9 real products. This gives users actionable quotes, not abstract recommendations.
